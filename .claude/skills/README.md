# .claude/skills/: the workflow skills

The AI-interface layer: portable `SKILL.md` files that turn the deterministic `fha` tools into a genealogy-aware research assistant. Each skill is **instructions plus `fha` invocations**, with no harness APIs, so it runs under any harness that reads the SKILL.md format. Two skills (`import-recordings`, `transcribe-audio`) also ship tested Python in their own `scripts/` folder for the model-dependent work no `fha` verb owns (_STANDARD.md §1).

**Start here:** [`_STANDARD.md`](_STANDARD.md) is the authoring contract every skill conforms to. [`today/`](today/SKILL.md) is the reference skill; copy its shape. Design lives in [`TOOLING_INTERFACE.md`](https://github.com/asielen/plaintext-family-history/blob/master/TOOLING_INTERFACE.md), the build order in [`TOOLING.md`](https://github.com/asielen/plaintext-family-history/blob/master/TOOLING.md) §15.

Deterministic work is in `fha` tools and judgment is in skills. **Only the human moves a claim to `accepted`.**

## The skills

| Skill | Status | What it does | Model tier |
|---|---|---|---|
| [`today`](today/SKILL.md) | **authored** | Session start: read `fha report`, narrate discoveries first (then the week in the family, briefly), offer the top item. Writes only what the human confirms while acting on the briefing, via `fha confirm discovery`/`cooccur`/`dismiss`, with the dry-run echoed first. Reference skill for `_STANDARD.md`. | Opus |
| [`on-this-day`](on-this-day/SKILL.md) | **authored** | The family's "on this day": run `fha calendar` (today, the week, or a month) and narrate the births, marriages, deaths and arrivals it returns, plainly, accepted claims only; at most two sentences of general world history, labelled as not from the owner's records; also a chat front end's opener. Read-only; invents no family detail; shared words keep living people private. | Sonnet |
| [`review-claims`](review-claims/SKILL.md) | **authored** | Stage C, the human gate: walk a source's `suggested` claims, capture accept/dispute/edit, write with `fha claim`; close with reindex + xref + touched-person view refresh + lint. | Opus |
| [`process-source`](process-source/SKILL.md) | **authored** | The pipeline driver: `fha process` (Stage A) + AI draft (Stage B) + hand-off to `review-claims`. Handles loose notes. | Opus |
| [`mine-transcript`](mine-transcript/SKILL.md) | **authored** | Invoked-only extraction over a transcript: selective `suggested` claims + anchors, stories to `## Stories`, transcript left intact. | Sonnet |
| [`write-biography`](write-biography/SKILL.md) | **authored** | Sourced prose from the draft queue: facts only from `accepted` claims, cite every factual sentence, AI-DRAFT markers until `fha confirm draft`. | Opus |
| [`research-next`](research-next/SKILL.md) | **authored** | Log-aware research leads: check the research log first, combine the report's gaps + open questions + working answers with era/place context; may write a guess as an `origin: agent` working answer on its question. | Sonnet |
| [`merge-identities`](merge-identities/SKILL.md) | **authored** | "Same person / two people" judgment: lay out the neighborhood evidence, propose, wait for human confirmation. Enacts a confirmed merge with `fha confirm merge` (dry-run preview first); the split stays hand-guided per SPEC §9. | Opus |
| [`place-research`](place-research/SKILL.md) | **authored** | Place history (loose citations OK): draft dated `history:`, propose registry entries via `fha confirm place`, offer `fha places geocode` for a place with no coordinates. Never edits coordinates without confirmation. | Sonnet |
| [`reconcile-site-edits`](reconcile-site-edits/SKILL.md) | **authored** | Keeps hand edits to the generated site: when a human hand-edits generated HTML, diff it against a pristine `fha site` baseline and fold the intent into the right source (`custom.css` / `notes/home.md` / a record / `fha.yaml` `site:`), then rebuild. Keeps `fha site` deterministic; every source write is human-confirmed. See [`docs/CUSTOMIZING_SITE.md`](https://github.com/asielen/plaintext-family-history/blob/master/docs/CUSTOMIZING_SITE.md). | Opus |
| [`photo-context`](photo-context/SKILL.md) | **authored** | Invoked-only caption improvement: gather what the archive knows about a photo (people, relationships, event, place), draft a better summary, and write it AI-marked via `fha photoindex set-summary` only after the human approves the exact text. Human captions are never overwritten. Runs only when asked, one photo or a small batch at a time. | Opus |
| [`find-photos`](find-photos/SKILL.md) | **authored** | Photo questions: resolve "show me grandma's photos" to the right filters, answer from the photo index in plain language (one line per physical photo), offer a clickable `fha photoindex gallery` page. Read-only; identification hands off to `tag-person`'s own prompt. | Sonnet |
| [`share-and-export`](share-and-export/SKILL.md) | **authored** | The guided sharing path: pick the right exporter (packet / gedcom / site / wikitree / backup) for the recipient, speak the privacy defaults in plain words before running, preview first, then report what went out and what stayed home. Import is not this skill. | Opus |
| [`import-notes`](import-notes/SKILL.md) | **authored** | Intake for old research notes: chunk a pile of freeform notes, propose a home per chunk under FILING_CABINET's routing rule (evidence → inbox → `process-source`; question / working answer / research-log entry / `notes/research/`), write only on the human's confirmed ruling. Drafts no claims; originals preserved by default, a scraps file dissolves only on explicit say-so after everything landed. | Opus |
| [`import-recordings`](import-recordings/SKILL.md) | **authored** | Intake for recordings: content-hash incoming audio/video against what is filed and skip duplicates (`fha media dedupe`), read the real recording date from the container (`fha media probe`, which allows for the container clock being UTC at the end of the recording while a filename clock is local at the start), group one sitting into one session source under `documents/interviews/{interviewee}-{yyyy-mm-dd}/`, always add a local whisper pass beside the app transcript (never replacing it), transfer speaker labels only under measured gates, and propose who is speaking without assigning it. Interactive by default; hands off to `process-source` / `mine-transcript`. Dedupe and probe are `fha media` verbs (`tools/media.py`); whisper (which needs a local model) and the speaker-label transfer (which works on the paired transcripts the skill produces) stay in the skill's own `scripts/`. | Sonnet |
| [`transcribe-audio`](transcribe-audio/SKILL.md) | **authored** | Local faster-whisper re-transcription of an archived or new recording via the skill's own `scripts/transcribe_audio.py`; attaches the pass as `whisper-transcript` beside the original transcript (both always kept), and offers the claim-by-claim audit of facts mined from the garbled original. | Sonnet |
| [`transcribe-source`](transcribe-source/SKILL.md) | **authored** | Words for image-only sources: scans have no searchable words, so a text search finds only what someone typed into the claims. Reads the images and writes a `[Page N]`-labeled `role: transcript` companion (`fha process --more`), marked `<!-- AI-DRAFT … -->` until a human checks it; the image stays the evidence of record. Runs from `process-source` (Stage A½, before claims are drafted) or standalone in bounded backfill batches. Drafts no claims; a contradiction with an accepted claim becomes a `## Q:` block. Its one blocked gap is in [`transcribe-source/GAP.md`](transcribe-source/GAP.md). | Opus |
| [`setup-interview`](setup-interview/SKILL.md) | **authored** | First-run setup: right after `fha install`, ask the researcher who he is, how he wants the tree numbered (`root_generation: self` or `children`), and his immediate family, as firsthand testimony from the one informant the archive is guaranteed to have. Mints his own person record directly (`sex:`, `living:`); writes one `source_class: authored` interview source and drafts `relationship`/`marriage` claims naming everyone with explicit `roles:` (never `birth` claims), all `status: suggested`; hands off to `review-claims`. Normally runs once per archive. | Opus |

Statuses: **authored** = the SKILL.md exists and was verified against the current tools and the lint invariant; the remaining gate is a **behavioral session check** against `example-archive/` (capture the transcript).

## Conventions (all skills)

- One folder per skill: `.claude/skills/{name}/SKILL.md`.
- Every skill obeys [`_STANDARD.md`](_STANDARD.md): suggested-only claims; `accepted` only via `fha claim` with a human decision; every AI pass recorded in the source's `ai_passes:` list; AI-DRAFT markers for prose; never edit below a GENERATED header or overwrite human text.
- No skill imports another. Skills connect only through documented hand-offs, such as `process-source` passing its drafted claims to `review-claims` or `today` offering one next skill to run; each skill's Flow names its own hand-offs.
- Verification is behavioral: run the skill against `example-archive/` and confirm the documented writes, graceful handling of messy input, and that `fha lint` still exits 1 with only the documented baseline warnings (`_STANDARD.md` §9).
